# 0026 — 기존 AI 노트에 로컬 계정 게이트를 연결하고 원격 멀티테넌시는 분리한다

- **날짜:** 2026-08-04
- **상태:** 채택됨

## 무엇을 결정했나

인증 뒤 별도 제품이나 대시보드를 만드는 대신, 승인·결제가 확인된 고객 세션만 **기존 AI 노트 제품 경로**(`/`, `/live`, `/meetings/*`, `/settings`, 기존 제품 API)에 들어가게 한다. 로그인·회원가입·운영자 화면만 별도 route group으로 두며 고객 로그인 성공 목적지는 기존 홈 `/`다.

고객 신청은 `승인 대기 → 결제 확인 필요 → 사용 가능` 순서로 전환한다. 운영자가 미결제·연체·차단으로 변경하면 해당 고객 세션을 즉시 폐기한다. 요금제 표시는 계정당 월 1,500엔 또는 월 9.9달러이고, 현재 단계의 결제 상태는 운영자가 수동으로 확인한다. 로그인·녹음 발행·요약·실시간 세션·번역 사용 횟수를 계정별로 집계하되 사용량으로 기능을 제한하지 않는다.

운영자 계정은 공개 가입을 금지한다. 최초 최고 운영자는 운영자 계정이 전혀 없을 때 로컬 설정 화면에서 한 번만 만들고, 이후 계정은 최고 운영자가 발급한 24시간·1회용 초대 링크로만 생성한다. 비밀번호는 scrypt로 파생해 저장하고, 운영자 로그인에는 암호화 저장된 TOTP 비밀키와 일회용 복구 코드를 사용한다. 고객·운영자 세션 쿠키는 분리된 불투명 토큰이며 `HttpOnly`, `SameSite=Lax`, HTTPS 요청의 `Secure`, 절대 만료를 적용한다. 승인·결제·차단·로그인·초대 변경은 로컬 감사 기록에 남긴다.

계정 제어 파일은 기존 `data/` 아래의 비공개 `data/system/`에 원자적으로 저장한다. 이 단계는 사용자가 요청한 **URL 확정 전 로컬 기능 검증**을 위한 것이다. 기존 회의·라이브러리·프로필·설정 데이터는 아직 원래의 단일 로컬 데이터 루트를 사용하므로, 서로 독립된 여러 고객사가 하나의 원격 인스턴스를 함께 쓰는 멀티테넌시 완료 상태로 간주하지 않는다.

## 왜

이전 구현은 인증 뒤 원래 만들던 녹음·실시간 전사·회의록 제품이 아니라 새 화면을 보여 주어 제품 연결 요구를 충족하지 못했다. route group을 분리하면 로그인 화면에는 제품 사이드바를 억지로 넣지 않으면서도, 인증 뒤 기존 제품 컴포넌트와 URL을 그대로 재사용할 수 있다.

반면 로컬 JSON 파일은 단일 프로세스 검증에는 충분하지만 다중 서버의 동시 갱신, 계정별 회의 데이터 격리, 결제 provider의 서명된 사건 처리를 보장하지 않는다. URL·클라우드·결제 provider가 정해지지 않은 상태에서 이를 흉내 내면 보안 경계를 과장하게 된다. 그래서 로컬 계정 게이트와 원격 멀티테넌트 저장소/결제 연동을 명시적으로 나눈다.

## 원격 배포 전에 반드시 교체할 경계

- 회의·라이브러리·검색 인덱스·프로필·설정을 `accountId` 기준으로 분리하고 서버에서 소유권을 검사한다.
- `data/system/auth.json`을 조건부 갱신과 다중 인스턴스 일관성을 제공하는 공유 트랜잭션 저장소로 옮긴다.
- 수동 결제 상태를 선택한 결제 provider의 서명 webhook과 결제 주기 상태 머신으로 교체한다.
- 로컬 전용 요청 가드를 실제 HTTPS host·reverse proxy 신뢰 경계에 맞게 재설계하고, 비밀키를 클라우드 비밀 저장소에서 주입한다.
- 계정/감사/사용량의 보존 기간, 개인정보 고지, 탈퇴·삭제 절차를 배포 지역 요구에 맞게 확정한다.

## 갱신 (2026-09-14)

"원격 배포 전에 반드시 교체할 경계" 중 첫 항목은 구현됐다. 회의·라이브러리·검색 인덱스·프로필·단어장은 `data/tenants/{sha256(accountId)}` 루트로 분리되며 모든 데이터 API·페이지가 세션에서 계정을 결정한다(`docs/ARCHITECTURE.md` "계정별 데이터 루트"). 같은 날 스트리밍 `finalize` 경로가 클라이언트가 보낸 `x-vision-account-id` 헤더를 신뢰하던 결함을 닫았다(세션 재조회 + `runWithAccountTenantData`). `data/system/auth.json`의 공유 트랜잭션 저장소 전환, 결제 provider webhook, 조직 권한·감사 로그는 여전히 후속 범위이므로 이 결정의 "상용 멀티테넌시 아님" 결론과 테스트 인스턴스 운영 원칙은 유지한다.
