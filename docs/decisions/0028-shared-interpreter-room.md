# 0028 — 공유 링크로 여는 1:1 통역 회의실과 게스트 세션 경계

- **날짜:** 2026-09-15
- **상태:** 채택됨 (2026-09-15 소유자 확인)

## 무엇을 결정했나

계정이 있는 사용자(**호스트**)가 **통역 회의실**을 만들고, 상대(**게스트**)는 호스트가 전달한 링크와 자동 생성 비밀번호로 이름만 입력해 입장한다. 두 사람은 각자 자기 기기에서 같은 회의실에 접속해 **같은 대화를 자기 언어 관점**으로 본다. 음성 전달은 하지 않는다. Zoom·Google Meet 같은 화상회의나 같은 방의 대화가 음성을 담당하고, 이 회의실은 옆에 띄워 두는 자막·번역 보조 화면이다.

1. **인원과 모드.** 첫 버전은 호스트 1명 + 게스트 1명(1:1)이다. 호스트는 회의실을 만들 때 `원격(화상회의)` 또는 `같은 방` 모드를 고른다. 모드는 마이크 정책과 화자 귀속 규칙을 결정하며 진행 중에는 바꾸지 않는다.
2. **참가자별 관점.** 각 참가자는 입장 시 자기 언어(`ko|en|ja|zh`)를 고른다. 내 발화 행은 `내 원문 + 상대에게 전달된 번역(검수용)`, 상대 발화 행은 `내 언어 번역 + 접을 수 있는 상대 원문(이해용)`으로 그린다. 세션 데이터는 하나이고 관점만 다르다.
3. **화자 귀속.** `원격` 모드는 발화가 들어온 참가자 기기가 곧 화자다. `같은 방` 모드는 호스트 기기 한 대만 마이크를 켜고 (1) 발화 언어가 어느 참가자의 언어인지 → (2) 언어로 못 가르면 직전 확정 발화의 Soniox speaker 라벨 연속성 → (3) 입장 시 각자 한 문장을 말해 speaker 라벨을 이름에 묶는 등록 → (4) 발화별 `내 말/상대 말` 수동 정정 순서로 정한다. 성문(voiceprint) 기반 영구 화자 식별은 범위 밖이다.
4. **게스트 세션 경계.** 게스트 쿠키는 `vision_guest_session`으로 고객·운영자 쿠키와 분리하고 **회의실 하나에만** 유효하다. 게스트의 모든 읽기·쓰기는 호스트 테넌트 루트의 해당 회의실 안에서만 일어나며, 계정 파일·다른 회의·라이브러리·단어장에는 닿지 않는다. 게스트 입장은 링크 토큰 + 비밀번호(scrypt 해시 대조) + 이름이 모두 있어야 하고, 실패는 회의실 존재 여부를 구분하지 않는 같은 응답이다. 비밀번호 시도는 회의실별 rate limit를 둔다.
5. **초대.** 회의실을 만들면 링크와 비밀번호가 한 번 생성된다. `초대하기`는 주소 한 줄, 비밀번호 한 줄, 유효 기간 안내 한 줄을 한 번에 클립보드에 복사한다. 비밀번호는 호스트 화면에서 다시 볼 수 있고 재생성하면 기존 게스트 세션은 폐기된다.
6. **수명.** 회의실은 호스트가 `회의 종료`를 누른 시각(`endedAt`)부터 **24시간** 뒤 게스트 링크가 만료된다. 종료 전에는 계속 유효하다. 만료 전 게스트는 재입장해 대화록과 AI 회의록 요약을 내려받을 수 있으며, 회의록 요약은 내려받을 때 **게스트가 언어를 고른다**(`ko|en|ja|zh`, 기본은 자기 언어). 호스트 언어가 아닌 요약은 요청 시 번역해 회의 디렉터리에 `summary.{lang}.md` 파생 파일로 캐시하고 원본 `summary.json`은 바꾸지 않는다. 만료 뒤 게스트 세션과 링크 토큰은 lazy sweep으로 정리하고, **회의 자체는 호스트 계정의 일반 회의로 영구 보존**한다. 종료하지 않은 회의실은 생성 후 72시간에 서버가 종료 처리한다(잊힌 회의실이 무한히 열려 있지 않게).
7. **저장과 발행.** 회의실은 호스트 테넌트의 회의 하나(`data/tenants/{host}/meetings/{id}/`)다. 진행 중 발화 이벤트는 app-api만 쓰는 `room-events.jsonl`(append, 단일 writer)에 durable append하고, 종료 시 기존 `saveGlobalMeetingSession()` 계약으로 `transcript.md`/`summary.json` pair를 발행한다. 원본 불변·단일 writer·rename 커밋 규칙은 그대로다. 회의실 메타(`room.json`: 모드, 참가자, 토큰 해시, 비밀번호 해시, `endedAt`, `guestExpiresAt`)는 app-api 소유 파일이며 상태 FSM은 `status.json`이 계속 소유한다.
8. **실시간 동기화.** 서버→클라이언트는 **SSE**(`GET /api/rooms/{id}/events`, Node route, `text/event-stream`)로 밀고, 클라이언트→서버는 기존 JSON POST다. WebSocket·별도 프로세스·외부 메시징 서비스는 도입하지 않는다. SSE는 `Last-Event-ID`로 재접속 시 놓친 이벤트를 다시 보낸다.
9. **외부 호출과 비용.** 전사는 각 참가자 브라우저가 60초 single-use 임시 키로 Soniox에 직접 붙는다(게스트도 회의실 세션으로 `temporary-key`를 받는다). 번역은 기존 `/api/translate`를 회의실 세션으로 호출한다. 사용량은 **호스트 계정에** 집계한다. 화면 문구에는 provider·모델명을 쓰지 않는다(ADR 0024).

## 왜

고객사는 한 화면을 같이 보는 지금의 글로벌 미팅이 아니라 "각자 자기 기기에서, 내 말이 상대에게 어떻게 전달됐는지 확인하면서" 대화하길 원한다. 검수(내 발화의 번역 확인)와 이해(상대 발화의 내 언어 번역)를 한 화면에서 주는 것이 가치이고, 음성은 이미 쓰는 화상회의가 맡으므로 우리가 오디오를 중계할 이유가 없다.

게스트를 계정 없이 받되 링크만으로는 못 들어오게 하는 것은 승인형 계정 게이트(ADR 0026)를 유지하면서 외부 상대를 최소 마찰로 초대하기 위해서다. 게스트 세션을 회의실 하나에 묶고 호스트 테넌트 안에서만 동작하게 하면 오늘 닫은 finalize 경계(ADR 0026 갱신)와 같은 계정별 데이터 루트 규칙을 그대로 지킬 수 있다.

같은 방 모드의 귀속을 언어 규칙만으로 하지 않는 이유는 두 사람이 잠깐 같은 언어(영어)로 말하는 순간 구분이 무너지기 때문이고, Soniox 화자 라벨만으로 하지 않는 이유는 유튜브 4개 연속 회귀에서 합쳐짐·과분리가 재현됐기 때문이다(`evals/`). 언어 → 라벨 연속성 → 등록 문장 → 수동 정정의 계층은 각 단계가 앞 단계의 실패만 보완하도록 설계했다.

SSE를 고른 이유는 현재 단일 Node 서버·Next route handler 구조에 인프라 추가 없이 얹을 수 있고, 클라이언트 쓰기는 이미 있는 POST 계약으로 충분하기 때문이다. 24시간 만료를 종료 시각 기준으로 둔 것은 "회의 끝나고 하루 안에 기록을 받는다"는 고객 요구를 그대로 옮긴 것이다.

## 버린 대안

- **음성까지 중계하는 자체 화상회의** — WebRTC·TURN·녹화 인프라가 필요하고 고객은 이미 Zoom/Meet를 쓴다. 기각.
- **게스트도 정식 계정 가입** — 승인·결제 게이트를 외부 상대에게 강요하게 된다. 기각.
- **링크만으로 입장(비밀번호 없음)** — 링크 유출이 곧 회의 유출이다. 소유자 요구로 비밀번호 필수.
- **WebSocket 서버** — Next route handler 밖에 별도 프로세스를 두어야 하고 Docker/터널 구성이 늘어난다. 1:1 자막 동기화에는 SSE로 충분해 기각. 다자 회의실로 확장할 때 재검토.
- **성문(voiceprint) 화자 식별** — Soniox에 없고 별도 서비스·생체정보 동의가 필요하다. 범위 밖.
- **게스트 링크를 생성 시각 기준 24시간** — 회의가 길어지거나 늦게 시작하면 진행 중 만료된다. 종료 시각 기준으로 확정.
- **게스트 다운로드를 대화록만** — 소유자가 AI 회의록 요약까지 허용하기로 결정.
- **게스트 회의록을 호스트 언어로만 제공** — 게스트가 내려받을 때 언어를 고르는 편이 실제 사용에 맞다고 소유자가 결정. 번역본은 파생 캐시 파일이며 원본 요약을 덮지 않는다.

## 갱신 기록

- **2026-09-25 — 문장 단위 확정과 문맥 재번역.** 고객 피드백("호흡에 따라 문장이 애매하게 끊겨 번역이 어색해진다")에 대응해 두 단계를 더했다. (1) 클라이언트는 Soniox 끝점을 바로 발화로 보내지 않고 `UtteranceCoalescer`(`src/lib/utteranceCoalescer.ts`)에 모은다. 문장 종결 부호로 끝나거나, 화자·언어가 바뀌거나, 1.8초 동안 이어지는 말이 없거나, 400자를 넘으면 조각을 합쳐 한 발화로 제출한다(마이크를 끄거나 회의가 끝나면 남은 조각을 즉시 제출). 합쳐진 조각의 live 번역도 이어 붙여 함께 보낸다. (2) 서버는 live 번역을 즉시 발행한 뒤에도 **모든** 상대 언어를 직전 발화 4개를 `<context>`로 넣은 프롬프트로 다시 번역해 `translation` 이벤트로 덮어쓴다(`translateText(..., { context })`). 프롬프트는 사투리·구어체를 표준 표현으로 옮기도록 지시한다. 화면은 live 문장을 먼저 보여 주고 몇 초 뒤 다듬은 문장으로 교체되며, 다운로드는 항상 마지막 번역을 쓴다. 발화당 상대 언어 수만큼 모델 호출이 늘어나는 비용은 호스트 사용량에 그대로 집계된다.
