한 줄 정의

승인형 고객 계정 뒤에 있는 회의 웹앱. 브라우저 녹음(마이크·탭 오디오) → Soniox 비동기/실시간 전사 → OpenRouter 작업별 모델 체인으로 교정·요약·번역 → 열람·수동 수정·검색·내보내기. Android 앱은 같은 웹을 감싼 WebView 셸.

가장 먼저 알아야 할 5가지

  • 원본 불가침: audio.webm·raw.md·segments.json은 생성 후 수정 금지.
  • 단일 writer: 파일마다 쓰는 모듈이 하나. 남의 파일을 쓰지 않는다.
  • rename이 커밋: temp → fsync → rename → 부모 디렉터리 fsync. 결과는 4가지 durability 상태.
  • 계정별 데이터 루트: 고객 데이터는 data/tenants/{sha256(accountId)}. 계정은 세션 쿠키에서만 결정.
  • TDD + FAKE: 테스트 먼저, 외부 서비스는 FAKE_SONIOX/FAKE_LLM/FAKE_FFMPEG로만.

실시간 경로 (글로벌 미팅 · 음성 입력)

/live는 서버가 60초 single-use Soniox 임시 키만 발급(/api/realtime/temporary-key)하고 브라우저가 WebSocket으로 stt-rt-v5에 직접 연결한다. 연결 상태는 sonioxConnectionStore가 소켓 이벤트로만 파생(폴링 아님). 번역·TTS는 /api/translate와 sonioxTts. 종료 시 대화록·회의록을 같은 finalize/publisher 계약으로 저장한다.

백그라운드 작업

  • 요약 워커: instrumentation.ts가 기동, runSummarizeTick()이 data/tenants/*를 각 컨텍스트로 순회. AI_NOTE_DISABLE_WORKER=1로 비활성.
  • 전사 모니터: dispatch를 시작한 요청 컨텍스트를 상속. 재시작 뒤엔 상세 조회가 resumeTranscription으로 재개.
  • 정리 sweep: guarded 접근이 lazy start. tombstone·.trash-{id}·late orphan만 수거.

코드 컨벤션

규칙의 우선순위는 AGENTS.md → 아키텍처·ADR → 테스트로 고정된 계약 → 구현이다. 아래는 코드에 실제로 강제되는 것(린트·테스트)과 문서로 합의된 것을 구분해 정리했다.

커밋

파일·이름 규칙

  • 컴포넌트 PascalCase.tsx, hook useX.ts, lib/domain camelCase.ts. 테스트는 같은 폴더의 __tests__/에 co-locate.
  • 테스트 전용 훅은 resetXForTests()/awaitXForTests() 접미사로 export. 프로덕션 코드가 호출하지 않는다.
  • 내부에서만 쓰는 심볼은 export하지 않는다(2026-09 knip 정리 기준). 예외: throw되는 Error 클래스.
  • 주석은 “왜”를 쓴다. 파일 머리에 모듈의 소유권과 불변식을 한 문단으로 둔다.
  • 사용자 문구·문서는 한국어, 식별자·타입·로그 코드는 영어. 화면 문구에 provider·모델명 금지(ADR 0024).

API 라우트 작성 패턴

// src/app/api/<surface>/route.ts
export const runtime = "nodejs";          // edge 금지
export const dynamic = "force-dynamic";   // data/ 읽는 라우트

export async function POST(request: Request, { params }: RouteContext) {
  const denied = guardLocalApiRequest(request);  // 1. 가장 먼저
  if (denied) return denied;
  const id = assertSafeId((await params).id);    // 2. params는 guard 뒤
  const fenced = await meetingFenceResponse(id); // 3. tombstone fence
  if (fenced) return fenced;
  const body = await parseBoundedJsonBody(request, 8 * 1024); // 4. bounded JSON
  const op = await tryAcquireMeetingOperation(id, "…");       // 5. lease
  if (!op) return publicErrorResponse("meeting_conflict", 409);
  try {
    // … lib 호출. status.json은 updateStatus(id, op.ownerToken, …)
    return jsonNoStore(toPublicMeeting(status));   // 6. allowlist DTO
  } finally { op.release(); }
}
R1
guard 먼저, side effect는 나중
params·body·fs·network·spawn보다 guardLocalApiRequest(request)가 앞선다. 테스트가 소스 순서를 검사한다.
R2
top-level process.env 금지
키·모드는 핸들러 안에서 지연 조회. next build는 시크릿·data 없이 통과해야 한다(build-green).
R3
오류는 static envelope
publicErrorResponse(code, status)의 {error:{code,message}}만. raw Error·path·provider 본문을 응답·로그에 넣지 않는다(safeLog).
R4
경로는 paths.ts만
meetingPaths(id)·libraryPath()·dataRoot()를 쓰고 process.cwd()/data를 직접 조합하지 않는다. 테넌트 루트가 자동 적용된다.
R5
잠금 순서 준수
meeting operation → artifact RW lease → status queue → library queue. 거꾸로 잡지 않는다. read lease 안에서 mutation 금지.

테스트 컨벤션

TDD

새 기능·버그 수정은 실패하는 테스트부터. 실패한 테스트를 완화·삭제하기 전에 원인과 재현을 먼저 확인한다.

격리

파일 I/O 테스트는 mkdtemp + process.chdir로 임시 cwd를 잡고 resetXForTests()로 모듈 상태를 초기화한다. 외부 호출은 FAKE_SONIOX=1 FAKE_LLM=1 FAKE_FFMPEG=1.

계약 테스트

라우트 인벤토리, 프롬프트 문구 드리프트, i18n 카탈로그 정렬, 고객 가이드의 provider명 부재처럼 “문서와 코드가 같은가”를 테스트로 고정한다.

UI 컨벤션 (docs/UI_GUIDE.md 요약)

  • 웜 베이지/브라운 팔레트(#FAF8F4 바탕, #2A2420 잉크, #5B4A42 액센트). 보라/그라데이션/글래스/글로우 금지.
  • 상태는 색만이 아니라 아이콘+텍스트. 소형 텍스트에 #9A8F84 금지(대비).
  • 독립 컨트롤은 44×44px 이상, focus-visible ring 분리. 같은 action group은 높이·radius·간격 통일.
  • 한국어 word-break: keep-all, 일본어 line-break: strict. URL·키·이메일만 break-all.
  • 모달은 AppDialog/AppDrawer만. 파괴적 동작은 색 외에 “버리기/영구 삭제” 텍스트 필수, 취소가 initial focus.
  • 오류 문장 순서: 무엇이 실패했는지 → 입력이 보존됐는지 → 다음 행동. raw path·ID·provider 출력 금지.
  • Android는 data-ai-note-android-app 속성으로 분기, 창 폭 기준 compact/medium/expanded(Material 3 Adaptive).
  • 320 / 390 / 1440 뷰포트에서 가로 오버플로 0을 E2E로 검증.

{title, topicSlug, oneLine, purpose, participants[], highlights[], discussion[], decisions[], actionItems[{owner,task,due}], risks[], followups[], body?}. body가 있으면 편집 가능한 structured 필드는 모두 비어 있어야 함(dual truth 거부). participants는 항상 [](참석자는 status.review).
library.json v1
{schemaVersion:1, libraryId, revision, defaultWorkspaceId, workspaces[], folders[], placements[]}. read mode missing|ready|corrupt|unsupported_version|io_error. corrupt에서만 fingerprint 확인형 rebuild.
auth.json
{version:1, accounts[], sessions[], invitations[], usage[], audit[]}. 비밀번호 scrypt, TOTP 비밀키 암호화, 복구 코드 해시.
tombstone
strict {id, deletedAt}. malformed/symlink는 delete_state_ambiguous로 fail-closed, 자동 복구 금지.

쓰기 · 잠금 · 내구성

커밋 프로토콜

durableFileOps: temp 작성 → 파일 fsync → rename(커밋) → 부모 디렉터리 fsync. 결과 4상태 not_committed / committed_durable / committed_best_effort(디렉터리 sync 미지원 환경) / committed_durability_pending(일시 실패). rename 뒤 실패는 rollback하지 않는다.

다단계 발행

finalize: hidden .finalize-{id}/에 intent(create-exclusive) → audio → status+receipt → 디렉터리 rename이 publish. pair: .summarize-{attempt}/ manifest prepared → preimage_durable → transcript_published → summary_published. 전사: segments 먼저, raw 마지막. 삭제: tombstone rename이 logical delete, 물리 정리는 나중.

잠금 계층

① meetingLifecycle operation(회의당 exclusive, owner token) → ② artifactLease read/write(pair 소비자는 read, publisher·delete·cleanup은 write) → ③ status queue → ④ library queue(absolute path 기준 process-global) · corpus queue. 역순 획득 금지. 원격 폴링 중에는 lease를 잡지 않는다.

파생 최신성 (freshness)

contentRevision.summary.basedOnTranscriptSha256 !== contentRevision.transcript.sha256이면 summaryOutdated. 저장 필드가 아니라 파생 값이다. 검색 카드·챗봇 근거는 outdated summary에 credit을 주지 않는다. revision 없는 legacy pair는 virtual fresh로 읽고 read가 write를 유발하지 않는다.

복구 원칙

재시작 뒤 attempt만 남으면 첫 pair read가 summarize_reconcile로 completed/resume/restore/interrupted/ambiguous를 판정한다. 모순된 hash·manifest는 덮어쓰지 않는다. corrupt registry는 원본을 private archive로 보존한 채 새 libraryId를 발급하고 클라이언트 generation epoch를 올린다. 백업은 data/ 볼륨 전체를 대상으로 한다.

운영 금지 목록: docker compose down -v, data/·tombstone·볼륨 삭제, 회의 디렉터리 이동, 운영자·고객 계정 초기화, git reset --hard/git clean/force push. 모두 명시적 승인이 있을 때만.

남은 과제 (우선순위)

1
배포 주소 복구 · 고정 도메인
Android APK와 고객에게 전달된 Quick Tunnel 주소가 DNS에서 사라졌다. aws login 재인증 → 서버 tunnel 로그 확인 → 도메인 확정(후보 note.goqual.com 미확정) → 이름 있는 Cloudflare Tunnel → APP_ORIGIN → 자동 재시작·외부 감시 → APK 재빌드. 모두 승인 뒤 실행.
2
서버 코드 갱신
GitHub push는 배포가 아니다. 서버에서 로컬 변경 유무를 먼저 보고한 뒤 git pull --ff-only && docker compose up -d --build. .env.production의 키·SMTP·APP_ORIGIN 존재 여부만 확인.
3
비밀번호 복구 메일
SES 발신 인증과 no-reply@goqual.com SMTP 자격증명. 코드에 하드코딩하지 않는다.
4
레거시 루트 fail-closed
paths.ts의 dataRoot()는 컨텍스트가 없으면 조용히 data/로 떨어진다. 인증된 경로에서는 오류로 만드는 편이 안전하지만 단위 테스트 다수가 이 fallback에 의존하므로 별도 작업으로 분리.
5
서버의 레거시 data/meetings 처리
테넌트 분리 이전에 만들어진 회의가 볼륨에 남아 있을 수 있다. 어느 고객에게 귀속할지는 소유자 결정 후 이동 스크립트로 처리(회의 디렉터리 이동은 승인 사항).
6
i18n 카탈로그 다이어트
1,151 키 중 Whisper 시절 문구·릴리즈 노트 문장이 남아 있다. 카탈로그는 DOM 텍스트 기반 MutationObserver 번역에도 쓰이므로 코드 grep만으로 지우지 말고 화면 스냅샷 기준으로 정리.
7
legacy LLM adapter 정리 여부
claude-cli·codex-cli·ollama adapter는 로컬 저장 설정 호환용으로 보존 중(문서 명시). 고객 배포에서 제거할지는 제품 결정.
